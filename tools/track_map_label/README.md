# track_map_label: 트랙 도면으로 위치 찾기와 라벨 만들기

대회장 조명에서 찍은 raw 사진마다 차가 트랙 도면의 어디에 있는지 찾는다.
찾은 위치로 도면의 내 차로(da)와 경계선(ll)을 사진에 투영해 라벨을 만든다.

## 왜 만들었나

2026-11-06 대회장 조명으로 다시 찍은 사진(`dataset_raw/20261106/session_180809`, 734장)에서는 2차 모델이 크게 흔들린다.
조명이 분홍, 빨강, 청록, 파랑으로 바뀌고 매트가 반사되기 때문이다.
사람이 라벨을 다시 달거나 2차 모델로 pseudo-label을 만들면, 모델이 틀리는 바로 그 장면에서 라벨도 틀린다.

트랙은 도면으로 고정돼 있다(10m x 6m).
사진 속 위치만 맞으면 라벨은 바닥 기하만으로 정해지므로, 조명과 상관없이 같은 정답을 얻는다.
앞으로 대회장에서 새로 찍는 데이터에도 같은 방법을 쓸 수 있다.

## 입력

| 입력 | 출처 |
|---|---|
| 트랙 도면 DXF (1:30 축척, A3) | `smoony0226/autorace2026` (private) `docs/2026Track 도면 시트1.dxf` |
| 카메라 내부 보정 K, D (1280x720) | `autorace2026/tools/camera_calib/result/limo.yaml` (2026-11-05, 재투영 0.38px). `cam.py`에 640x360으로 줄여 넣음 |
| 카메라 장착 위치 | 높이 0.19m, 뒷바퀴 축에서 앞 0.244m (`autorace2026` camera_calib README의 줄자 실측값) |
| 카메라 기울기 | 외부 보정이 아직 없어 직선 구간 사진에서 추정(`pitch_est.py`). 약 4° 아래. 이 값이면 차선 간격이 약 510mm로 도면 500mm와 맞음. 추적할 때 프레임마다 3.5~4.5°에서 다시 고름 |
| raw 사진 | `/camera/color/image_raw` 1280x720 jpg |

도면에서 뽑은 선(`lines.json`)과 지도(`paint.npy`, `dt_mm.npy`)는 팀 비공개 도면에서 나온 것이고 용량도 커서 저장소에 넣지 않았다. 아래 순서로 다시 만든다.

## 실행

경로는 `config.py`의 기본값(동아리 RTX PC)을 쓰고, 환경변수로 바꿀 수 있다.

| 환경변수 | 뜻 |
|---|---|
| `TRACK_LABEL_WORK` | 지도(`map/`)와 결과(`results/`)를 두는 작업 폴더 |
| `TRACK_LABEL_RAW` | raw 사진 폴더 |
| `LIMO_TRAIN_ROOT` | LimoPro_train 폴더 (`scripts/train_seg.py`, 2차 가중치) |
| `HYBRIDNETS_CKPT` | 검증에 쓸 HybridNets 가중치 |

```bash
# 0) 도면 -> 지도 (한 번만). ezdxf가 필요하다
python parse_dxf.py "2026Track 도면 시트1.dxf" $TRACK_LABEL_WORK/map/lines.json $TRACK_LABEL_WORK/map/dxf_plot.png
python build_map.py $TRACK_LABEL_WORK

# 1) 세션 전체 위치 추적 -> results/poses_v2.json  (RTX 3070 Ti 약 25분)
python track_session.py

# 2) 도면 라벨 검증 -> results/agree.npy, results/validate_montage.jpg
python validate.py
```

ROS·CUDA 환경변수가 섞이지 않게 `env -u PYTHONPATH -u LD_LIBRARY_PATH`로 LimoPro_train의 `.venv/bin/python`을 쓴다.

## 방법

1. **도면 지도** (`parse_dxf.py`, `build_map.py`): DXF의 선과 스플라인을 mm 좌표로 바꾼다. 차선은 폭 20mm짜리 윤곽선 쌍으로 그려져 있어서, 닫힘 연산으로 칠해진 표시 마스크를 만든다(5mm/px).
2. **사진 표시** (`localize.markings`): 바닥 영역의 밝기 top-hat으로 밝은 표시를 뽑는다. 조명색에 덜 민감하다. 카메라 모델로 바닥 평면에 펴서(BEV) 차체 좌표로 바꾼다.
3. **위치 점수** (`track.score2`): 양방향 거리를 쓴다.
   - 사진 표시가 도면 표시에서 얼마나 떨어져 있는지
   - 그 위치라면 카메라에 보여야 할 도면 표시가 사진에 있는지

   한쪽만 쓰면 횡단보도나 글자처럼 표시가 빽빽한 곳에 아무 사진이나 붙는다.
4. **추적** (`track_session.py`):
   - 10장마다 전역 탐색을 하고, 서로 떨어진 상위 후보 2개를 남긴다.
   - 후보마다 앞뒤 25장을 이어 추적하고, 모든 결과를 프레임별 후보로 저장한다.
   - Viterbi로 734장 전체에서 이어지는 경로 하나를 고른다. 비용 = 점수/5 + 이동 벌점(프레임당 90mm, 12° 초과분) + 건너뛴 프레임 수 x 3.
   - 고른 경로에서 빠진 프레임은 앞뒤 위치를 보간한 뒤 그 근처에서 다시 맞춘다.
5. **라벨** (`render.py`):
   - 차 위치에서 차로를 따라 30mm씩 나아가며 좌우 경계선을 찾아 내 차로를 그린다.
   - 정지선처럼 차로를 가로지르는 선은 통과하고, 그 너머에 경계가 이어지지 않으면 차로 끝으로 본다.
   - 점선 틈은 같은 차로 폭으로 잇는다.
   - 사진 픽셀마다 바닥 평면으로 역투영해 도면 라벨을 읽는다. 렌즈 왜곡까지 반영한다.

## 라벨 규칙

기존 학습 라벨(`ego_v2_ys_split`)과 맞췄다.

- **ll:** 내 차로의 왼쪽·오른쪽 경계선만. 노란 선, 지그재그, 3차선 구간의 흰 점선을 포함한다.
- **da:** 두 경계선 사이. 차로 안의 횡단보도, 글자, 마름모도 da에 포함한다.
- 횡단보도, 마름모와 글자, 출발 체커, A/B 글자 영역은 도면 좌표 상자로 경계 후보에서 뺐다(`render.EXCL`).

## 결과 (session_180809, 734장)

경로 고르기 비용을 고쳐 추적을 다시 돌리는 중이다. 끝나면 이 PR에 결과 수치와 확인 이미지를 추가한다.

1차 추적(앵커 25장 간격, 프레임별 최고 점수)과 고친 라벨 그리기로 낸 중간 결과:

| 위치 점수 | 장수 | 도면 라벨 vs 2차 HybridNets 예측 da IoU 중앙값 | ll IoU 중앙값 |
|---|---:|---:|---:|
| 25 이하 | 373 | 0.922 | 0.371 |
| 25~40 | 157 | 0.904 | 0.317 |
| 40 초과 | 33 | 0.827 | 0.364 |

2차 모델이 잘 맞는 쉬운 장면에서 둘이 일치하는지 본 값이다. 2차 모델이 무너지는 대회장 조명 장면에서는 낮게 나오는 것이 맞다.
ll은 선이 몇 픽셀밖에 안 돼서 조금만 어긋나도 IoU가 크게 떨어진다. 또 2차 모델은 옆 차로 선까지 칠하므로 낮게 나온다.

1차 추적의 알려진 문제: 위쪽 직선과 두 번째 직선이 이 각도에서 거의 똑같이 보여서, 50~100번 프레임이 두 번째 직선의 반대 방향으로 잡혔다(점수는 오히려 더 좋음). 그래서 Viterbi로 경로 전체가 이어지는지를 보고 고르게 바꿨다.

## 한계와 남은 일

- **3차선 구간:** 저장소 README의 결정("3차선 구간은 전체를 칠한다")을 아직 반영하지 않았다. 지금은 내 차로만 칠한다.
- **갈림길과 T자 구간:** 육각형 A/B 갈림길과 T자 구간에서 '내 차로' 규칙이 정해지지 않았다. 지금은 차로를 가로막는 선을 만나면 끊는다.
- **ll 굵기:** 도면 실제 폭(20~40mm)으로 칠해서, 기존 라벨이나 2차 모델 출력보다 가늘다. 학습에 쓰기 전에 기존 라벨 굵기에 맞출지 정해야 한다.
- **10/27 학습 데이터:** 같은 트랙 배치로는 맞지만 대회장 데이터보다 덜 정확하다(`check_train_frames.py`). 카메라를 받는 경로(UVC MJPG)와 장착 각도가 달랐을 수 있다. 이 데이터는 이미 라벨이 있어서 도면 라벨이 필요하지 않다.
- **가려짐:** 트랙 위 사람, 라바콘, 다른 차는 고려하지 않는다.
- **차선 폭:** 도면 500mm 기준. 저장소 README에는 550mm로 적혀 있다.
