# 다중 작업 3차 결과 (`multitask-v3`, 2026-11-12)

2차(`multitask-v2`) best에서 이어서 H100에서 학습했습니다. 설정과 근거는 [`docs/MULTITASK_V3_TRAINING.md`](../../docs/MULTITASK_V3_TRAINING.md)에 있습니다.
릴리즈 가중치는 **epoch 11**(`best_score.pt`, val의 da+ll IoU+mAP50 합이 가장 높은 epoch)이고, 릴리즈 [`multitask-v3`](https://github.com/mastic-choi/LimoPro_FOSCAR_Vision/releases/tag/multitask-v3)에 있습니다.

## 한 줄 요약

- **표지판 검출이 크게 좋아졌습니다.** 콘을 뺀 mAP50이 기존 test 0.931 → **0.969**, 대회장 test 0.937 → **0.979**, test_bag 0.952 → **0.987**입니다. 기존·대회장 test의 A/B AP는 0.81~0.89에서 0.95~0.99로 올랐습니다.
- **먼 표지판(14~18px)을 맞히는 비율이 55% → 83%로 올랐습니다.** 18px 이상은 92~97%에서 96~97%입니다.
- **신호등 뒤 땡땡이 모니터를 불빛으로 잡는 오탐이 61개(36장) → 4개(3장)로 줄었습니다**(193장, 점수 0.3 이상).
- **콘 오탐이 2,365개 → 189개로 줄었습니다**(콘 사진 1,363장, 점수 0.4 이상). 대신 √넓이 14px 미만의 아주 먼 콘은 일부러 학습에서 빼서 거의 잡지 않습니다.
- **차선 ll이 0.010~0.016 내렸습니다**(기존 test 0.816 → 0.802, test_bag 0.826 → 0.810). 실차에서 조향에 영향이 있는지 확인이 필요합니다.
- 구조, 입력, 출력은 1·2차와 같아서 **추론 코드에 가중치만 바꿔 넣으면 됩니다.** 점수 분포는 바뀌었으니 주행 코드의 점수 기준은 다시 확인해야 합니다([점수 보정](#점수-보정)).

## 바꾼 것 (2차 대비)

| | 2차 | 3차 |
|---|---|---|
| 시작 가중치 | 1차 best.pt | 2차 best.pt (epoch 14) |
| 신호등 뒤 방해 모니터 | 없음 | 학습 사진의 40%에 그려 넣음(단색 / 땡땡이 반반, 실제 카메라 효과 전부). 라벨 없는 음성 샘플 |
| 작은 박스 | 전부 학습 | √넓이 14px 미만은 무시(켜진 불빛은 제외) |
| A/B/주차 | 그대로 | 든 이미지를 2배 자주 뽑음 |
| 조기 종료 | 15 epoch 고정 | 최대 120 epoch, val loss가 5 epoch 동안 안 내려가면 멈춤 |
| best 고르기 | val 점수 | val loss 최저, 단 val da+ll이 시작보다 0.01 넘게 낮으면 제외(차선 보호) |
| 점수 보정 | 학습 중 보정 손실 | 학습 뒤 val로 클래스별 temperature |
| lr, 손실 비중 | 검출 머리·BiFPN 1e-3, 나머지 1e-4, 검출 손실 2배 | 같음 (120 epoch에 0이 되는 감소) |

H100 PCIe 1장, batch 32, bf16 AMP, epoch당 약 175초. 학습 기록은 [`train_run/`](train_run/)에 있습니다.

## 어떤 가중치를 골랐나

학습은 epoch 12에서 멈췄습니다. val loss는 epoch 7이 가장 낮았고 그 뒤 5 epoch 동안 더 낮아지지 않았습니다.
그런데 val loss가 최저를 갱신한 epoch(1, 3, 4, 6, 7)은 모두 val 차선 IoU가 시작(2차)보다 0.01 넘게 낮아 차선 보호에 걸렸습니다. 그래서 **학습 스크립트의 `best.pt`는 2차 가중치 그대로**였고, 실제 후보는 epoch 7(`best_val_loss.pt`)과 epoch 11(`best_score.pt`)이었습니다.

세 가중치를 같은 test로 비교했습니다(점수 0.4 이상, `scripts/eval_mt_compare_montage.py`).

| | 2차 (= best.pt) | epoch 7 | **epoch 11 (릴리즈)** |
|---|---:|---:|---:|
| 기존 test 표지판·신호등 1,039개: 맞음 / 클래스 틀림 / 놓침 | 892 / 30 / 117 | 931 / 15 / 93 | **932 / 9 / 98** |
| 대회장 test 274개: 맞음 / 클래스 틀림 / 놓침 | 236 / 5 / 33 | 241 / 4 / 29 | **247 / 2 / 25** |
| 콘 뺀 mAP50 (기존 / 대회장 / bag) | 0.942 / 0.941 / 0.969 | 0.969 / 0.975 / 0.981 | **0.975 / 0.980 / 0.989** |
| 차선 ll (기존 / bag) | **0.816 / 0.826** | 0.805 / 0.810 | 0.802 / 0.810 |
| 흰 가로선 IoU (대회장) | 0.605 | 0.620 | **0.645** |
| 땡땡이 모니터 가짜 불빛 (점수 0.3) | 61 | **2** | 4 |

(이 표의 mAP는 신호등 몸체를 포함한 10클래스 평균이라 아래 표와 정의가 조금 다릅니다.)

epoch 7과 11은 차선이 사실상 같고, 표지판 구분과 흰 가로선은 epoch 11이 낫습니다. 갈림길 사진 한 장에서 주행영역이 옆 차선으로 번지는 증상도 epoch 7이 더 심했습니다(`compare/lane_test.jpg`).

검출 mAP50은 2차와 같은 정의입니다(신호등 몸체 제외, 기존 test에는 콘 포함). **기존 test의 mAP가 거의 그대로인 것은 콘 때문입니다.** 기존 test에 든 콘의 82%가 14px 미만이고, 3차는 이 크기를 일부러 무시하게 학습해 콘 AP가 0.57 → 0.27로 내려갔습니다. 14px 이상 콘만 보면 0.887 → 0.970으로 올랐습니다.

## 점수 보정

학습 스크립트는 `best.pt`(= 2차)로만 temperature를 맞췄기 때문에, epoch 11로 다시 맞췄습니다(`scripts/eval_mt_finalize.py`, val 626장 = 합성 326 + 콘 300). 결과는 [`hybridnets_mt_v3_calib.json`](hybridnets_mt_v3_calib.json)이고 릴리즈에도 넣었습니다.

| 클래스 | pedestrian | sign_A | sign_B | bump | slow | parking | traffic_light | red | yellow | green | cone |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| T (3차) | 0.442 | 0.718 | 0.487 | 0.621 | 0.382 | 0.479 | 0.341 | 0.536 | 0.503 | 0.449 | 1.058 |

- 쓰는 법: `p' = sigmoid(logit(p) / T[클래스])`. T < 1이면 점수를 0과 1 쪽으로 벌립니다(높은 점수는 더 높게, 낮은 점수는 더 낮게).
- 보정 뒤 검출 점수의 ECE(점수와 실제 정답률의 차이)는 대회장 test 0.120 → 0.053, test_bag 0.120 → 0.045로 줄었습니다. 기존 test는 콘 예측이 대부분이라(콘 T ≈ 1) 0.076 → 0.077로 그대로입니다.
- 이 PC(Apple M4, fp32)에서 계산했습니다. 같은 방법으로 2차를 다시 맞추면 학습 서버(bf16) 값과 클래스별 T가 대부분 0.02 안에서 같고, sign_B는 0.04, sign_A는 0.08 차이가 났습니다.
- **2차와 3차의 점수 분포가 다릅니다.** 주행 코드가 날 점수에 고정 기준(예: 0.4)을 쓰고 있다면, 바꿔 넣은 뒤 실차에서 기준을 다시 확인하거나 보정 점수를 쓰세요.

## 한계

- 차선 ll이 2차보다 0.010~0.016 낮습니다. 학습 중 차선 보호 기준(0.01)을 넘은 값이라, 실차에서 2차와 같은 코스로 비교해 보는 것을 추천합니다.
- 14px 미만 콘(아주 먼 콘)은 거의 잡지 않습니다. 주행 로직이 아주 먼 콘에 의존한다면 2차가 낫습니다.
- test의 표지판·신호등과 모니터는 합성이라 실제 대회장 성능은 실차 확인이 필요합니다.
- 시드 1개입니다. 대회장 test·test_bag은 클래스마다 표지판이 적어 AP 0.02~0.1 차이는 우연일 수 있습니다.
- lr은 120 epoch에 맞춘 감소라, 12 epoch에서 멈출 때까지 1e-4 → 8.7e-5로 거의 줄지 않았습니다. 다음 학습에서는 감소 길이를 실제 학습 길이에 맞추는 것이 좋습니다.
